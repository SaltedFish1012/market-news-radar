# X 指定账号轮询与言论推送设计

日期：2026-10-12。状态：待用户审阅；本文件描述目标行为，尚未实施产品代码。

## 目标与依赖

用户已确定：跟踪指定 X 账号，定期读取公开帖子，支持“每条都推”和“筛选后推送”两种模式；消息明确标记为“X 用户言论”，保留原文和作者身份。

复用现有新闻归档、重要性分类、可选 AI 分析、SQLite 通知队列及 Telegram／Bark。标的关联使用 `2026-10-12-market-sessions-design.md` 中的统一内部代码；采集器的去重、游标和发帖作者识别不依赖行情供应商。

## 现状与接入方案

当前后台任务只有 RSS、Alpaca 新闻、长桥报价／新闻和通知，没有 X 连接器。`Engine.ingest` 对普通级别消息只归档，且标题、摘要分别截断为 300、1500 字符；因此不能不加区分地把 X 帖子交给原流程。

采用 X 官方用户帖子接口轮询指定账号，以 Bearer Token 验证；用户名查询获得稳定用户 ID，再调用 `/2/users/{id}/tweets`，使用 `since_id` 及分页增量采集。定期读取符合用户选定方向，复用现有异步 HTTP 客户端；实时过滤流作为后续方案，当前不接入。第三方 RSS 可以继续由现有 RSS 功能读取，但不能替代本轮作者身份、持久游标和账号级策略的验收。

## 页面设置与默认值

在“行情与新闻”中增加独立的 X 区域：

| 配置 | 约定 |
| --- | --- |
| `x_enabled` | 默认 `false`；开启前必须有 API Token 和至少一个启用账号 |
| `x_bearer_token` | 按现有密钥机制保存，页面只返回已配置状态；留空保留、明确勾选才清除 |
| `x_poll_interval` | 默认 120 秒，允许 60–3600 秒；以整轮开始时间安排下一轮，不因账号数额外叠加固定休眠 |
| `x_accounts` | 最多 20 个账号，可逐个添加、停用、移除；用户名去掉前置 `@`，大小写去重并验证 X 用户名形式 |
| 账号 `push_mode` | `all` 或 `filtered`；新增账号默认 `filtered` |
| 账号 `include_replies` | 默认 `false`，允许开启 |
| 账号 `include_reposts` | 默认 `false`，允许开启；引用帖作为作者发帖保留并标明引用对象 |
| 账号 `keywords` | 最多 50 个，大小写不敏感；为空时使用全局主题关键词 |
| 账号 `related_symbols` | 手动绑定统一标的代码，作为明确配置的关联，不宣称实际市场影响 |

旧配置缺少 X 字段时自动使用以上默认值，不改动既有密钥与新闻来源。保存后只重启受影响的采集任务。账号列表和 Token 只在本机配置，不要求用户在聊天中提供密钥。

## 采集、分页与恢复

1. 为账号解析并持久化稳定用户 ID，保留实际返回的用户名、显示名和个人主页链接。账号改名不会造成同一帖重复推送。
2. 账号第一次成功读取只归档最新一页（最多 10 条）作为初始快照，不推送已有帖子；成功完成归档后保存起始游标。网络失败不能把初始化标为成功。
3. 正常采集使用已完成游标 `since_id`，请求发布时间、作者及引用关系字段，增量分页收集帖子。API 返回的完整正文是保存依据；如果返回长帖扩展正文，优先保存该正文。
4. 每账号每轮最多取 5 页，每页最多 100 条；有剩余分页时持久化本批次的起始游标、分页位置和已观察最大 ID，下一轮继续同一批次。只有整批完成才推进已完成游标，不能仅见到最新一页就跳过较旧的未处理新帖。
5. 归档与去重成功后才记录处理进度。重启、网络错误或任务取消不跳过帖子；重试已归档帖子时不会再次加入通知队列。
6. API 参数调整、Token 更换和轮询间隔变化保留同一用户的历史游标；重新添加已跟踪的用户继续原游标。新的用户 ID 按首次初始化处理。
7. 休眠期间可以取消任务，停止后旧任务不得继续归档或通知。各账号错误独立处理，一个不可访问账号不阻止其他账号采集。

轮询频率不是时延保证；实际延迟还取决于上游限流、网络、分页数量和通知通道。服务离线较久后的补采仍归档；超出已有 `news_max_age_minutes` 的帖子不会作为新鲜突发消息推送。

## 两种推送模式

### 每条都推：`all`

每条新的、符合帖子类型开关、时间有效且未超过新闻有效期的帖子直接进入通知队列，普通新闻级别也会通知。无需命中英语财经重大性词；空关键词不会阻止此模式。首次快照和重复帖子仍不推送。

### 筛选后推送：`filtered`

满足以下任一条件时推送：正文命中账号关键词（没有账号关键词时使用全局主题关键词），或现有规则将消息分类为 `high`／`critical`。两组关键词都为空时，仅保留重要性规则判断。显式绑定标的本身不强制将普通帖子提升为重大事件。

匹配使用实际正文，不只检查截短标题；支持中文和其他语言的配置关键词。AI 分析不阻塞首次通知，也不成为决定是否首报的必要条件。未匹配内容仍归档，可在新闻中心检索。

## 数据保存、作者与展示

新闻表增加来源类型和 X 元数据，包含发帖 ID、稳定作者 ID、用户名、显示名、作者主页、完整原文、引用／转帖关系及编辑历史 ID。普通 RSS 和现有新闻使用兼容默认值。标题由作者和正文短摘要组成，完整原文独立保存，不受普通摘要的 1500 字符截断影响。

新闻中心显示固定标签“X 用户言论”、作者显示名及 `@用户名`、发布时间、原文链接，并提供完整原文展开。原文保留字面文本，不使用普通 RSS 的 HTML 剥离函数改写；界面按纯文本安全渲染，不执行其中的 HTML 或脚本。作者显示名是平台返回的公开资料，不将平台认证标记等同于言论已证实。转帖和引用帖明确区分发帖作者与被引用作者，不能把被引用内容写成当前账号本人发表的原话。

通知标题使用“X 用户言论 · @用户名”；正文保留作者、发布时间、正文摘录、原文链接和配置关联标的，适配现有 Telegram／Bark 长度限制，长文通过原文链接阅读。归档中的完整文本与推送摘录分开，明确标明摘录。

原文保留不依赖 AI。若启用 AI，既有重要性条件与调用上限继续适用；分析要求区分“账号发表了某种言论”和“言论内容已被证实”。本轮不新增单独的自动翻译调用；用户可查看原文及既有中文分析。

## 去重与编辑

去重使用稳定的 `X + post_id`，不使用显示名或账号配置名作为身份。编辑历史 ID 对应同一编辑链，归档更新最新版本及编辑时间，界面标记“已编辑”，不把每次编辑当成一条全新的言论重复首报；首次首报保留原发送内容便于核对。

回复、引用与转帖是独立的帖子事件，是否采集由账号开关决定；同一发帖 ID 被多个配置或重试获取时只归档和首报一次。数据库迁移可重复执行，游标与编辑映射持久化，旧新闻记录保持可读。

## 错误、额度与任务状态

- `401`／`403`：记录明确的认证或权限状态，不输出 Token 或带认证内容的异常；等待设置改变或适度退避，不紧密循环重试。
- `429`：尊重 `Retry-After` 或上游限流重置时间；没有可靠时间时指数退避，最高 15 分钟。其他网络／服务端错误从 5 秒退避到最高 5 分钟，正常轮询恢复后重置。
- 额度不足等付费访问错误：显示“额度／账单访问异常”和可操作的设置提示，不自动充值或换用浏览器登录抓取。
- 删除或无法访问的账号：单独标记账号错误，保留历史记录和游标；其余账号继续运行。
- 数据连接页显示总体启用状态、最近成功轮询、每账号最新帖时间及错误。不能将“未收到新帖”自动判为断线。

官方 API 按使用量计费。设置页注明启用采集会产生 API 读取费用，并链接开发者计费与消费上限设置；本轮不猜测美元单价，也不承诺免费实时监控。API 访问域名固定为官方域名，Token 只放 Authorization 请求头。

## 本轮交付界限

交付指定公开账号的轮询采集、作者和原文归档、两种推送模式及设置管理；不增加私信读取、推荐时间线采集、浏览器登录抓取、媒体 OCR 或全网舆情搜索。X 连接器保持来源身份，不将用户言论自动升级为已核实财经事实。
