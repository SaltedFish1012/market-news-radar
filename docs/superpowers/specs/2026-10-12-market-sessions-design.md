# 多市场标的配置与美股四时段行情设计

日期：2026-10-12。状态：待用户审阅；本文件描述目标行为，尚未实施产品代码。

## 目标与实施顺序

用户已确定：先补齐美股盘前、盘中、盘后、夜盘的行情展示与价格预警，建立统一的标的、市场、币种和时区配置，然后加入韩股、日本市场及 A 股的历史行情。

第一阶段建立统一标的配置及美股四时段报价、K 线、预警；第二阶段使用同一配置接入其他市场的 Yahoo 历史行情。X 指定账号监控按 `2026-10-12-x-monitoring-design.md` 独立实施，共用新闻、设置和通知管线。

验收重点是用户能辨别看到的价格属于哪个市场、哪个时段、什么时间、什么来源，并能按时段选择价格预警。现有美股自选、登录、新闻、技术指标和设置必须继续可用。

## 现状与方案选择

- `app/market.py` 的 Yahoo 请求关闭盘前盘后，Alpaca 固定使用 IEX，日线收盘判断固定纽约 16 点。
- `app/connectors.py` 的长桥订阅统一追加 `.US`，报价回调仅转发价格，丢弃时段和上游时间。
- `.env.example` 已有夜盘开关，但设置页未管理该开关。
- 长桥报价已附加到市场总览 API，前端没有使用它；图表、资金和 CSV 固定美元、美东时间。
- 股票代码校验拒绝数字和 `^` 开头的标的。

采用“长桥负责美股四时段实时报价和完整时段 K 线，Yahoo 负责公共历史行情”的方案，复用既有连接器和研究模块。仅修改 Yahoo 参数无法补齐夜盘及实时预警；全面更换行情供应商则增加迁移和账户成本。Alpaca IEX 保留，其覆盖限制在页面说明；本轮不增加 Alpaca SIP/BOATS 账户接入。

## 统一标的配置

新增集中定义标的元数据的模块，配置项包含：

| 字段 | 含义 |
| --- | --- |
| `symbol` | 稳定内部代码；现有美股保持 `NVDA`，其他市场保留市场后缀，例如 `005930.KS`、`7203.T`、`600519.SS`、`^N225` |
| `name` | 用户可编辑的显示名称，供应商名称作为补充 |
| `market` | `US`、`KR`、`JP`、`CN` |
| `asset_type` | `stock`、`etf`、`index` |
| `currency` | 美元 `USD`、韩元 `KRW`、日元 `JPY`、人民币 `CNY` |
| `timezone` | IANA 时区：`America/New_York`、`Asia/Seoul`、`Asia/Tokyo`、`Asia/Shanghai` |
| `provider_symbols` | 各供应商代码映射，例如美股长桥 `NVDA.US`，Yahoo `NVDA` |

自选列表继续保存代码数组；增加对应的标的元数据列表。价格规则、新闻关联、数据库和 API 使用同一个内部代码。保留旧美股代码和 API 的 `symbol` 参数，统一处理 `.US` 别名。数字代码的前导零不能丢失；指数前缀 `^` 允许用于指数类型。代码必须经过结构验证和 URL 路径编码，不能仅放宽为任意字符串。

旧 `settings.json` 和 `watchlist.json` 缺少新字段时自动补齐原有美股元数据，保持密钥、AI 配置、RSS、规则和 revision 的值。新增字段仍使用原子保存和版本冲突保护。既有配置不在读取时重写；用户保存设置时持久化新增字段。

未加入自选的历史查询仍支持常见代码形式，由明确的后缀推断上述市场和默认元数据；无法识别的代码要求用户配置，不猜测市场。供应商返回的币种与配置不一致时提示数据异常，不能偷偷更改金额单位。

## 报价、交易时段与数据鲜度

统一时段值为 `pre`、`regular`、`post`、`overnight`；无法确认时段的报价为 `unknown`。`all` 仅用于查询与规则选择，不作为真实报价的时段值。

每份报价保留内部代码、币种、来源、交易时段、上游报价时间、服务器接收时间、价格及交易状态。优先使用长桥返回的 `trade_session`；不能凭最新收到数据或本机时钟将旧报价标为当前交易时段。补充保存最近的各时段报价，不把盘后和夜盘覆盖成一个无时段的价格。

长桥开启夜盘通过页面配置并同步 SDK；旧环境变量值作为初始配置来源。启动时获取报价快照，随后使用推送更新。只订阅长桥支持并存在对应映射的美股标的，不对其他市场追加 `.US`。取消或重新应用设置时，旧连接的后续回调不得写入新配置。

实时预警只接受上游时间距接收时间不超过 120 秒、未来偏差不超过 5 秒的有效报价，本轮阈值固定。重复或倒序报价、盘后修订数据、非正常交易状态、非有限价格不得用于预警。旧报价仍可显示其原时间，并明确标为“历史报价／已过期”；连接正常不等于价格新鲜。

数据库新增带时段的报价存储，采用可重复执行的迁移；保留旧报价记录，旧记录没有上游时间和时段时标为未知，不用于实时报警。现有新闻和预警记录不丢失。

## 页面与 API

市场总览显示各标的市场、币种、来源、报价时间和交易时段。选中美股时展示四时段报价卡，缺少数据的时段显示“暂无报价”。主价格优先使用有效的长桥报价；选择某一时段时只显示该时段价格，不能用其他时段冒充。没有长桥报价时仍可显示已有公共价格，但明确注明“常规时段公共报价”和供应商时间。

图表增加常规时段／盘前／盘后／夜盘／全部时段选择，API 增加可选 `session` 参数，缺省为 `regular`，保持既有研究行为。新增 `longbridge` 历史行情源。实时价格和历史 K 线来源不同时分别标明，避免把公共 K 线称为长桥实时数据。

查询结果带标的元数据、选择时段、实际数据覆盖、报价和收盘状态。缓存键包含标的、供应商、周期和时段。自选列表可以混合市场，每项独立显示结果和来源；某个市场接口失败不阻止其他标的展示。页面新增标的及元数据编辑控件、夜盘开关、规则时段选择，保存后即时生效。

报价涨跌幅统一相对该报价时间之前最后一根已完成的常规日线收盘价计算，显示基准时间；基准日线的实际收盘时间必须不晚于这笔报价时间，不能用报价发生之后的收盘价。没有可信基准时显示空值，不使用区间首根 K 线或其他时段价格。图表和交易记录按标的市场时区显示。资金、净值和 CSV 字段使用标的币种；金额不做跨币种自动换算。

## K 线与收盘判定

- 长桥美股分钟历史行情使用包含延长时段的官方接口，保留返回的会话标签；从统一数据中按用户选择过滤，夜盘需要显式开启。
- Yahoo 美股分钟行情在用户选择延长时段时开启 `includePrePost`，依据供应商返回的交易时段元数据标记盘前、常规、盘后。Yahoo 没有可信夜盘时返回“不支持夜盘”的明确结果，不补造夜盘。
- Alpaca IEX 标明部分时段覆盖；本轮不承诺完整盘前、盘后或夜盘。请求不支持的时段时提示选择长桥。
- 日／周线保留供应商定义的常规日／周 OHLC，不将四时段简单拼成供应商日线。非分钟周期选择盘前、盘后、夜盘时明确提示使用分钟周期。
- 日线收盘依据市场时区和供应商的实际收盘时间判断，处理提前收市。周线在有可靠末次交易日收盘依据时才标为完成。元数据缺失时，当前日／周采用保守的未完成状态，不把纽约 16 点用于所有市场。
- 时段标签和夜盘日期使用带时区时间与供应商交易日信息，支持美国夏令时和跨午夜；周末、假期、午休没有数据时不生成虚构 K 线。

## 四时段价格预警

沿用价格高于／低于、约 5 分钟涨跌幅四种规则；增加规则允许的时段集合。旧美股规则默认允许四个时段，用户可选择仅常规、仅夜盘或任意组合。

价格比较、短时涨跌幅缓冲和冷却按“标的＋时段＋规则”隔离；不会拿盘中最后一笔与夜盘第一笔当作连续 5 分钟价格。超过 370 秒没有连续数据后重建基准，第一笔不作为跨越阈值的证据。实时报价上游时间用于涨跌幅窗口，服务器时间用于接收与发送观测。

预警正文明确包含标的、币种、时段、报价时间、触发规则、来源；未知时段或过期报价只展示，不触发。其他市场本轮仅接入历史行情；没有实时连接时，界面说明价格预警尚无数据，不用历史 K 线伪装实时报警。

## 其他市场历史行情与策略边界

在第一阶段统一配置可用后，以 Yahoo 接入韩股 `.KS`／`.KQ`、日本股票 `.T`、日经指数 `^N225`、沪深股票 `.SS`／`.SZ`。保留现有 5 分钟／1 小时／日／周周期，实际是否有数据取决于上游；界面明确显示延迟、缺失和分钟历史区间限制。

各市场复用 K 线展示和 EMA、RSI、MACD、布林带计算。指数允许查看指标，不作为可直接买卖的股票运行成交回测。本轮保留现有美股常规时段回测；其他市场和美股延长时段的成交回测返回明确的未支持提示，避免现有碎股、单股全仓和简单下一根开盘模型被当作符合当地交易规则的结果。未来另行实现各市场成交约束及费用后再开放。

新闻关联和 AI 结果校验采用统一代码体系，AI 提示扩展为已配置市场的标的。该阶段不自动承诺当地媒体或监管公告覆盖；现有主题词和来源仍由用户配置。
